Tessera Engine Internal Architecture & Contributor Guide

This document is written strictly from the perspective of an engine developer working on the engine's C++20 and Vulkan codebase. It details the execution lifecycle, class responsibilities, file organization, Vulkan pipeline internals, compute/graphics shaders, and step-by-step instructions for extending the engine, adding features, and fixing bugs.

ℹ Codebase Standards

Tessera is built with C++20, compiled using MSVC on Windows and Clang on macOS/Linux. Rendering is native Vulkan 1.2 with cross-platform ray tracing abstractions. Physics uses Jolt Physics, scripting uses Sol2 Lua 5.4, and the UI uses Dear ImGui (Docking).

1. Engine Lifecycle & Frame Loop

The entire application lifecycle is driven by src/main.cpp through the EngineApp class:

main()
  → EngineApp::Run()
      → InitWindow()             // GLFW window, borderless hit testing, icon setup
      → InitVulkan()             // VulkanContext, swapchain, pipelines, subsystems
      → InitScene()              // Default nodes, Jolt physics, audio, Lua scripting
      → MainLoop()               // While !glfwWindowShouldClose:
          → glfwPollEvents()
          → InputManager::Update()
          → GameLoop::Update()   // If Play Mode: Lua scripts & Jolt physics tick
          → DrawFrame()          // Multi-view Vulkan render passes & ImGui submission
      → Cleanup()                // Flush GPU queues, destroy pipelines, shutdown singletons

The DrawFrame() Submission Sequence

Each frame submitted to the GPU executes the following synchronized sequence:

  1. Acquire Next Image: vkAcquireNextImageKHR retrieves a swapchain framebuffer image index.
  2. Buffer Synchronization & Streaming:
    • WorldPartitionManager::Update(): Updates camera distance/frustum priority and triggers DirectStorageQueue reads.
    • RayTracingManager::SyncScene(): Rebuilds BLAS acceleration structures for modified geometry and updates the TLAS instance buffer.
    • MeshletManager::SyncScene(): Clusters active meshes into meshlets and executes CPU/GPU frustum and backface cone culling.
    • CameraRelativeCoordinator: Computes 64-bit double-precision camera offsets to eliminate vertex jitter.
  3. Offscreen Multi-View Passes:
    • View 0 (Editor Viewport): Renders the active edit scene into m_offscreen (RGBA16F HDR).
    • View 1 (Game / Play View): Renders the active game camera scene into m_cameraPreviewOffscreen.
  4. Shadow Mapping Pass: m_pipeline.RenderShadowPass() generates 4 directional sun cascades plus point/spot shadow maps.
  5. G-Buffer & Occlusion Prepass: Writes linear depth and surface normals for SSAO, GTAO, and occlusion culling.
  6. Forward+ PBR Shading Pass: Evaluates clustered lighting, area lights (LTC), VXGI 3D voxel cone tracing, and hardware ray queries.
  7. Decals, Volumetrics & Ocean Passes: Projects decals, ray-marches volumetric clouds and fog, renders ocean waves, and computes fluid foam particles.
  8. Post-Processing & Temporal Upscaling: Evaluates Depth of Field, Motion Blur, Bloom down/up sampling, HDR Tone Mapping (ACES), and DLSS/FSR 3/XeSS temporal reconstruction.
  9. ImGui Editor Overlay Pass: Renders viewport dockspaces, gizmos (ImGuizmo), timeline sequencers, inspector panels, and menu bars directly into the swapchain command buffer.
  10. Present: vkQueuePresentKHR flips the presented image to the display.

3. The Vulkan Rendering Pipeline In-Depth

Tessera's rendering architecture lives primarily in src/Renderer/VulkanPipeline.cpp and src/Renderer/VulkanContext.cpp.

UniformBufferObject (UBO) Memory Layout

The global camera and environment properties are uploaded once per view to binding 0 using the following aligned struct:

struct UniformBufferObject {
    glm::mat4 view;              // Camera view matrix
    glm::mat4 proj;              // Camera projection matrix (Vulkan clip space)
    glm::vec4 cameraPos;         // Camera world position (.xyz) + padding (.w)
    glm::vec4 ambientColor;      // Ambient sky light intensity & colour
    glm::vec4 sunDirection;      // Normalized direction to the primary sun light
    glm::vec4 sunColor;          // Sun RGB radiance + intensity in .w
    glm::vec4 fogColor;          // Distance fog color + density in .w
    glm::vec4 timeParams;        // x = time (s), y = deltaTime, z = sin(time), w = frameIndex
    glm::mat4 cascadeViewProj[4];// Cascaded Shadow Map split view-projection matrices
    glm::vec4 cascadeSplits;     // Far depth split distances for cascades 0..3
    int numLights;               // Active clustered dynamic lights count
    int enableShadows;           // Shadow mapping master toggle
    int enableGI;                // Global illumination master toggle
    int padding;
};

Push Constants Layout

To avoid descriptor rebinding between draw calls, per-object parameters are passed directly via Vulkan Push Constants (≤ 128 bytes):

struct MeshPushConstants {
    glm::mat4 modelMatrix;       // 64 bytes: Local-to-world model matrix
    glm::vec4 baseColor;         // 16 bytes: Material diffuse/tint color
    float roughness;             // 4 bytes: PBR microfacet roughness
    float metallic;              // 4 bytes: PBR metallic factor
    int materialFlags;           // 4 bytes: Bitfield (hasAlbedoMap, hasNormalMap, hasAOMap...)
    uint32_t objectId;           // 4 bytes: Node ID for GPU viewport mouse-picking
};

4. Shaders Catalog (shaders/)

Shaders are written in GLSL (Vulkan-flavoured) and precompiled into SPIR-V (.spv) binaries via glslc. Runtime shader graph materials are compiled on demand.

Shader File Stage Pipeline Role
shader.vert Vertex Transforms vertices with skinning or model matrices, computes TBN tangent frames, and projects into camera-relative clip space.
shader.frag Fragment Master PBR lighting pass: Cook-Torrance BRDF (GGX D, Smith G, Schlick F), 4 cascade shadow PCF, clustered lights, LTC area lights, and VXGI cone tracing.
prepass.vert / .frag Vert / Frag Depth and surface normal prepass. Outputs linear view-space depth and world normals used by SSAO, GTAO, and contact shadows.
skinning.comp Compute High-performance GPU skeletal linear blend skinning. Evaluates bone armatures and writes skinned vertex buffers before rasterization passes.
shadow.vert / .frag Vert / Frag Cascaded shadow map depth capture pass for directional sun and point/spot omnidirectional shadow maps.
ssao.frag / ssao_blur.frag Fragment Horizon-based ambient occlusion sampling hemispherical normals followed by a depth-aware bilateral blur filter.
ssr.frag Fragment Screen-Space Reflections: hierarchical ray-marching against the G-buffer depth buffer with roughness cone jitter.
ocean.vert / .frag Vert / Frag Phillips spectrum ocean wave displacement, surface normal calculation, underwater refraction, foam cresting, and specular sun glints.
cloud_volume.frag Fragment Ray-marched 3D volumetric clouds with Henyey-Greenstein phase scattering, beer-lambert light extinction, and wind advection.
fluid_sim.comp / fluid_composite.frag Compute / Frag GPU Position-Based Fluid simulation: density constraints, surface smoothing, foam particle advection, and screen-space fluid composite.
taa.frag Fragment Temporal Anti-Aliasing with 16-phase Halton sub-pixel jitter, motion vector velocity reprojection, and Catmull-Rom history bicubic filtering.
bloom_down.frag / bloom_up.frag Fragment Dual-filtering 13-tap downsampling and 9-tap tent upsampling for thresholded HDR emissive bloom.
composite.frag Fragment Final post-process composite: ACES Filmic tonemapping, vignette, chromatic aberration, 35mm film grain, and LUT colour grading.

5. Scene Graph, Node Lifecycle & Hierarchy

Every entity in a Tessera scene inherits from Node (defined in src/Scene/Node.h). The scene graph maintains ownership through std::shared_ptr<Node> in m_nodes.

Transform Propagation Math

Nodes store local position, rotation (Euler degrees), and scale. World matrices are evaluated hierarchically:

glm::mat4 Node::GetLocalTransformMatrix() const {
    glm::mat4 mat = glm::translate(glm::mat4(1.0f), position);
    mat = glm::rotate(mat, glm::radians(rotation.y), glm::vec3(0, 1, 0));
    mat = glm::rotate(mat, glm::radians(rotation.x), glm::vec3(1, 0, 0));
    mat = glm::rotate(mat, glm::radians(rotation.z), glm::vec3(0, 0, 1));
    mat = glm::scale(mat, scale);
    return mat;
}

glm::mat4 Node::GetWorldTransformMatrix(const Scene& scene) const {
    if (parentId == 0) return GetLocalTransformMatrix();
    auto parent = scene.GetNodeById(parentId);
    if (!parent) return GetLocalTransformMatrix();
    return parent->GetWorldTransformMatrix(scene) * GetLocalTransformMatrix();
}

6. Engine Developer How-To Guides

Guide A: How to Add a New 3D Node Type

  1. Create src/Scene/Nodes/3D/MyNewNode.h and .cpp inheriting from Node.
  2. Set nodeType = NodeType::Custom (or add a new enum in Node.h).
  3. Implement Serialize() and Deserialize() using SimpleJson.
  4. Register creation factory in src/Scene/SceneNodes.cpp (e.g. Scene::AddMyNewNode()).
  5. Expose inspector controls in src/UI/NodeInspector.cpp inside the node properties switch.
  6. Add source file to set(SOURCES) and set(HEADERS) in CMakeLists.txt.
  7. Add a unit test in tests/MasterTestSuite.cpp to verify lifecycle and serialization.

Guide B: How to Add a New Vulkan Render Pass

  1. Create your GLSL shader in shaders/my_effect.frag.
  2. Register shader compilation in CMakeLists.txt via tessera_compile_shader(my_effect.frag my_effect_frag.spv).
  3. Add pipeline creation in VulkanPipeline::CreateGraphicsPipelines() with target render pass and layout.
  4. In VulkanOffscreen.h, declare any required intermediate color/depth attachments.
  5. In main.cpp (DrawFrame()), bind the pipeline (vkCmdBindPipeline), push descriptors, and issue vkCmdDraw() between GPU profiler markers (gpuBegin("My Effect") / gpuEnd()).

Guide C: How to Expose a New Subsystem to Lua

  1. Open src/Scripting/LuaScriptSystem.cpp.
  2. In Init(), create a new Lua table binding using Sol2: 
    auto myTable = m_lua.create_named_table("MySubsystem");
myTable["do_something"] = [](float value) {
    MySubsystem::Get().DoSomething(value);
};
  3. Document the new API in docs/systems-scripting.html.
  4. Add a unit test in tests/MasterTestSuite.cpp under [LuaScripting] verifying execution.

Guide D: How to Build and Run Unit Tests

Tessera features an automated headless test suite with 87 tests verifying all engine math, serialization, physics, ray tracing, and streaming:

# Build test suite in Release mode:
cmake --build build --config Release --target EngineTestSuite

# Execute test suite:
.\build\Release\EngineTestSuite.exe

# Expected output:
# RESULTS: 87 PASSED, 0 FAILED (~710 ms)

Guide E: Versioning & Releases

This documentation describes Tessera v1.0.0. The engine follows Semantic Versioning (MAJOR.MINOR.PATCH):

  • MAJOR: incompatible changes, such as a Lua API removed or renamed, or a .scene / .tess format that older versions can't read.
  • MINOR: new features that keep existing projects and scripts working.
  • PATCH: bug fixes only.
  • Pre-releases add a suffix: 1.1.0-beta.1.

The version is set in one place: the VERSION file at the repository root. CMake reads it at configure time and generates everything else from it:

  • build/generated/Core/Version.h: Tessera::Version::String, Major, Minor, Patch and the TESSERA_VERSION_* macros. Used by the splash screen, Help > About, saved projects (engineVersion) and the Vulkan application info.
  • The Windows executable's file properties (src/resources.rc).
  • docs/version.js: the version badge on every page of these docs.
# To release a new version: edit VERSION, then re-run the build (CMake reconfigures itself)
echo 1.1.0 > VERSION
cmake --build build --config Release

A malformed VERSION (anything that isn't MAJOR.MINOR.PATCH[-prerelease]) stops the CMake configure with an error. Commit the regenerated docs/version.js along with the VERSION change.
