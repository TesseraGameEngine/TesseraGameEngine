Tessera Game Engine Documentation

Welcome to the complete, definitive technical reference manual and user guide for the Tessera Game Engine. Tessera is a modern, high-performance, multi-threaded 3D and 2D game engine built from the ground up in C++20 with a Vulkan 1.2 rendering backend, integrated JoltPhysics, FBX / glTF skeletal animation with GPU skinning, spatial audio, A* NavMesh pathfinding, Godot-style authoritative multiplayer networking, and an embedded Lua 5.4 scripting environment.

ℹ Engine Philosophy: Modern, Modular & Authoritative

Tessera is designed around unified scene graphs, data-oriented memory buffers, and clear authority models. Whether developing an open-world action RPG, an indie platformer, or a multiplayer cooperative experience, every subsystem—from rendering and decimation to physics and replication—is cleanly decoupled and exposed via both an intuitive ImGui editor and an expressive Lua API.

1. High-Level Engine Architecture

The engine architecture is divided into decoupled core modules, orchestrated by the main engine loop (src/main.cpp and src/Gameplay/GameLoop.cpp):

Subsystem Implementation Path Key Responsibilities & Technologies
Vulkan Graphics Pipeline src/Renderer/ Vulkan 1.2 Forward+ renderer: clustered lights (including LTC Area Lights), multi-scattering PBR with skin / hair / eye models and Parallax Occlusion Mapping, cascaded and point-light shadows with screen-space contact shadows, reflection probes, baked GI and Real-Time Voxel Global Illumination (VXGI), GTAO + Specular Occlusion, SSR, volumetric fog, TAA, HDR post chain, GPU skinning, instancing, multi-material glTF/FBX submeshes, texture compression, and a runtime Visual Shader Graph.
Scene Graph & Entity System src/Scene/ Hierarchical node tree (Node, MeshNode, CharacterNode, UINode), transform propagation, JSON serialization, and clipboard management.
Level of Detail (LOD) & Simplification src/Scene/MeshSimplifier.* Distance-based LOD switching, draw-distance culling, and in-engine Quadric Error Metric (QEM) edge-collapse decimation (LOD1 50%, LOD2 25%, LOD3 10%).
Physics & Dynamics src/Physics/ JoltPhysics simulation backend, Static, Kinematic, Dynamic rigidbodies, constraints (Fixed, Hinge, Slider, Spring, Cone-Twist), ragdolls, and character raycasting.
Dual Animation Engine src/Animation/ Skeletal matrix & dual-quaternion skinning, Two-Bone Analytical IK, FABRIK solvers, Blend Shapes / Morph Targets, Visual Animation State Machine graph, and In-Engine Cutscene & Cinematic Sequencer.
Spatial Audio & DSP Mixer src/Audio/ 3D positional audio attenuation, Master/SFX/Music/Voice sub-buses, Doppler effect, DSP Reverb, Chorus, Distortion, Filters, and 3D Reverb Zones.
Navigation & AI Pathfinding src/Navigation/ NavMesh voxel rasterization, slope/step filtering, convex navigation polygon extraction, A* search, funnel string pulling, and NPC patrol steering.
Authoritative Multiplayer Networking src/Networking/ Client-Server architecture, Godot-style multiplayerAuthority, local peer IDs (1=Server, 2+=Clients), state replication packets, authority shielding, and RPCs.
Embedded Scripting Runtime src/Scripting/ Lua 5.4 VM with automatic node binding, lifecycle callbacks (OnInit, OnUpdate, OnCollision), input polling, physics manipulation, and RPC dispatch.
In-Game Video & Screen Displays src/Video/ Real-time video playback on 3D mesh surfaces (TVs, cinema screens, smartphones, CCTV, billboards) and fullscreen/PiP cutaway transmissions. Features GIF decoding, sprite-sheet atlases, procedural broadcast channels, CRT scanlines, and real-time HDR screen emission bouncing into VXGI and SSR.
Editor UI & Workspace src/UI/ Dear ImGui workspace, custom borderless window chrome with draggable titlebar, Project Files Viewer, dockable panels, ImGuizmo 3D transform manipulators, Node Inspector, Timeline, Shader Graph canvas, and State Machine editor.
Live Telemetry & Resource Profiler src/Monitoring/ Real-time CPU and GPU profiling, FPS/frame-time statistics, game-isolated memory, CPU, disk, network, and node telemetry with dynamic exponential smoothing.
Multi-Platform Standalone & Web Export src/Export/, src/Project/ Windows standalone single-file bundling, Linux Standalone & SteamOS packaging with turnkey launch.sh and .desktop profiles, and zero-dependency WebGL 2.0 / HTML5 export with embedded assets and unified controls.

2. Project Directory Structure

Tessera projects follow a clean, standardized folder structure automatically managed by the engine:

MyGameProject/

├── MyGameProject.tess      # Project configuration & settings file (JSON)

├── assets/

│   ├── models/                 # 3D Meshes (.fbx, .gltf, .glb, .obj) & LOD chains

│   ├── textures/               # PBR texture maps (.png, .jpg, .tga, .bmp)

│   ├── audio/                  # Audio clips (.wav, .ogg, .mp3)

│   └── fonts/                  # TrueType / OpenType fonts (.ttf, .otf)

├── scenes/

│   ├── main.scene              # Primary start scene (JSON node hierarchy)

│   └── level2.scene            # Additional gameplay scenes

└── scripts/

    ├── PlayerController.lua    # Lua actor and gameplay scripts

    └── NetworkSync.lua         # Multiplayer replication and RPC scripts

3. Engine Quickstart Guide

Step 1: Launching the Editor

Run TesseraGameEngine.exe. If no project is passed via command-line arguments, the engine opens the default project or prompts you with the Project Manager modal.

Step 2: Creating a New Project

  1. Click File → New Project... (Ctrl+N).
  2. Enter a Project Name (e.g. FantasyRPG) and choose a parent workspace folder.
  3. The engine creates the folder structure, initializes FantasyRPG.tess, sets up default scenes, and loads the editor viewport.

Step 3: Spawning Nodes into the Scene

Open the Add Node Palette by pressing Ctrl+A or right-clicking in the Scene Hierarchy:

  • Engine Internal Architecture & Contributor Guide — Deep technical guide for engine developers: Vulkan pipeline flow, shaders catalog, file/class map, and how-to guides.
  • Linux Build & Standalone Export Guide — Native compilation on Linux, export templates, turnkey launch.sh packaging, and Steam Deck integration.
  • To add an environment floor, choose 3D Objects & Primitives → Plane.
  • To add a directional sun, choose Entities & Lighting → Directional Light.
  • To add an interactive character, choose 3D Objects & Primitives → Character NPC.

Step 4: Assigning 3D Model Assets to Nodes

  1. Select your node (e.g., Humanoid NPC) in the Scene Hierarchy.
  2. In the Inspector panel (right), locate the 3D Model Asset slot directly below the Name field.
  3. Click Browse... and select an imported .fbx or .gltf character file (e.g., knight.fbx).
  4. The engine immediately copies the asset to assets/models/, extracts skeleton/bone joints, uploads mesh buffers to the GPU, and updates the viewport.

Step 5: Testing Gameplay in Play Mode

Press F5 on your keyboard or click the Play button on the Viewport toolbar. The engine switches into live gameplay mode: physics are simulated, character patrol routines execute, and Lua scripts run. Tessera enforces a Clean Slate Input Architecture: brand new games start with zero unsolicited default controls, meaning cameras and entities stay exactly where you placed them until you define their behaviors via Lua scripts or Input Action bindings. (Optional debug spectator camera can be enabled via code if desired). Press Esc (or the Stop button) to exit Play Mode and return to editing.

Command-Line Options

OptionEffect
--game --scene=<file>Run a scene as the game, without the editor.
--screenshot=<file.png>Save the rendered image and exit. In editor mode it skips the project hub and saves the 3D viewport.
--screenshot-frame=<N>Frame to capture (default 90).
--texture-compression=off|standard|highTexture compression: off, BC1/BC3 (default) or BC7. Normal maps use BC5. --no-texture-compression = off.
--bake-lightingBake the scene's lightmaps and GI volume at startup and save <scene>.lightmap / <scene>.gi; a screenshot waits for the bake.

Generated data lives in cache/textures/ (compressed textures) and cache/shadergraphs/ (compiled shader graphs). Both can be deleted; they are rebuilt when needed.
