Linux Build & Standalone Export Guide

Complete guide for building the Tessera Game Engine natively on Linux and packaging turnkey standalone games for Ubuntu, Debian, Fedora, Arch Linux, and Valve SteamOS / Steam Deck.

ⓘ Cross-Platform Standalone Export

You can export a standalone Linux game while running the Tessera Editor on Windows or Linux! The exporter leverages Godot-style precompiled export templates (templates/linux/TesseraGameRunner.x86_64) to generate turnkey packages with POSIX launchers and Steam Deck shortcuts.

1. Native Linux Engine Compilation

Tessera compiles natively on 64-bit Linux with GCC 11+ or Clang 14+ (C++20 standard), Vulkan 1.2, and X11/XCB or Wayland.

1.1 Install System Dependencies

Install the required C++ compilers, CMake, Vulkan developer libraries, and X11 windowing packages:

Ubuntu / Debian / Linux Mint:

sudo apt update && sudo apt install -y \
    build-essential cmake git curl zip unzip tar pkg-config \
    autoconf autoconf-archive automake libtool libtool-bin \
    libvulkan1 libvulkan-dev vulkan-tools mesa-vulkan-drivers \
    libx11-dev libxrandr-dev libxinerama-dev libxcursor-dev libxi-dev

Fedora / Red Hat / CentOS:

sudo dnf groupinstall "Development Tools"
sudo dnf install -y cmake git vulkan-loader-devel vulkan-tools \
    mesa-vulkan-drivers libX11-devel libXrandr-devel libXinerama-devel \
    libXcursor-devel libXi-devel autoconf automake libtool

Arch Linux / Manjaro / SteamOS (Desktop Mode):

sudo pacman -S --needed base-devel cmake git vulkan-devel \
    vulkan-tools vulkan-mesa-layers libx11 libxrandr libxinerama \
    libxcursor libxi

1.2 Dependency Management with vcpkg

Third-party libraries (GLFW, GLM, ImGui, ImGuizmo, Lua, Jolt Physics, and OpenFBX) are managed cleanly via Microsoft vcpkg:

# Bootstrap vcpkg in your user directory if not already installed
git clone https://github.com/microsoft/vcpkg.git ~/vcpkg
~/vcpkg/bootstrap-vcpkg.sh

# Install required Linux libraries
~/vcpkg/vcpkg install \
    glfw3:x64-linux \
    glm:x64-linux \
    imgui[docking-experimental]:x64-linux \
    imguizmo:x64-linux \
    lua:x64-linux \
    joltphysics:x64-linux \
    unofficial-openfbx:x64-linux

⚠ Note on Header-Only STB

Header-only image/font libraries are isolated under thirdparty/stb/ in the repository, avoiding conflicts with system STB packages.

1.3 Configuring and Building

Run CMake targeting an isolated build folder (e.g., build-linux):

# 1. Configure with the vcpkg toolchain
cmake -B build-linux -DCMAKE_BUILD_TYPE=Release -DCMAKE_TOOLCHAIN_FILE=~/vcpkg/scripts/buildsystems/vcpkg.cmake

# 2. Build the full editor executable
cmake --build build-linux --target Tessera -j$(nproc)

# 3. Build and run the 88-test offline test suite
cmake --build build-linux --target EngineTestSuite -j$(nproc)
./build-linux/EngineTestSuite

System Vulkan Loader Integration

The engine's CMakeLists.txt automatically prioritizes Ubuntu/Debian's official system Vulkan loader (/usr/lib/x86_64-linux-gnu/libvulkan.so) over vcpkg's headless loader. This guarantees that VK_KHR_xcb_surface, VK_KHR_xlib_surface, and VK_KHR_wayland_surface windowing extensions are active for GLFW window presentation.

1.4 Running Inside Virtual Machines (VMware / VirtualBox)

Virtual machine hypervisors do not expose native hardware Vulkan drivers. Mesa provides Lavapipe (lvp), a high-performance CPU software rasterizer capable of executing the full Vulkan 1.2 pipeline:

VK_ICD_FILENAMES=/usr/share/vulkan/icd.d/lvp_icd.json ./build-linux/Tessera --scene scenes/main.scene

2. Generating Export Templates

Similar to Godot Engine, Tessera utilizes precompiled export templates. To generate the standalone Linux binary template:

cmake --build build-linux --target linux_export_template

This automatically copies the compiled binary to templates/linux/TesseraGameRunner.x86_64. Whenever a game is exported, this binary is bundled into the distribution package and renamed to <GameTitle>.x86_64.

---

3. Exporting a Standalone Linux Game

3.1 Using the Editor Modal (Ctrl+B)

  1. Open your project or scene in the Tessera Editor.
  2. Press Ctrl + B or choose File → Export Standalone Game...
  3. Set Target Platform to Linux Standalone (x86_64 / SteamOS).
  4. Specify your Game Title (e.g., MyGame) and Destination Folder.
  5. Select your target display resolution:
    • Steam Deck Native (1280x800 16:10)
    • 720p HD (1280x720)
    • 1080p Full HD (1920x1080)
    • 1440p QHD (2560x1440)
    • 4K Ultra HD (3840x2160)
    • Fullscreen Toggle
  6. (Optional) Toggle Dual Proton / Wine Runner to bundle Windows player fallback binaries for hybrid testing.
  7. Click Export Game.

3.2 Anatomy of an Exported Linux Package

exports/MyGame_Linux/
├── MyGame.x86_64       # Native Linux 64-bit ELF game binary (from template)
├── launch.sh                 # Turnkey POSIX shell script (auto-chmod, library path)
├── MyGame.desktop      # FreeDesktop application & Steam shortcut
├── game.agconfig             # Game boot manifest (title, resolution, starting scene)
├── input_bindings.json       # Gamepad, keyboard & mouse action bindings
├── README_LINUX.txt          # Turnkey player instructions & Steam Deck setup
├── shaders/                  # Precompiled SPIR-V Vulkan shaders (*.spv)
├── scenes/                   # Packaged scene hierarchy files (*.scene)
├── assets/                   # Textures, 3D models, audio, fonts
└── scripts/                  # Lua 5.4 gameplay scripts (*.lua)

3.3 Playing on Desktop Linux

cd exports/MyGame_Linux
chmod +x launch.sh
./launch.sh

3.4 Playing on Valve Steam Deck & SteamOS

  1. Switch to Desktop Mode on your Steam Deck (or open the desktop Steam client).
  2. In the top menu, click Games → Add a Non-Steam Game to My Library...
  3. Click Browse... and select launch.sh or MyGame.x86_64 inside your exported game folder.
  4. Click Add Selected Programs.
  5. Switch back to Gaming Mode. Your game is now directly launchable with full gamepad mapping, suspend/resume, and MangoHud performance overlays!
---

4. Cross-Exporting Windows Games from Linux

Linux developers can export ready-to-run Windows standalone games (single-file self-extracting .exe or directory bundles) directly from the Tessera Editor running on Linux, without needing Wine, MinGW, or a Windows virtual machine.

4.1 Windows Export Templates

The engine ships with precompiled Windows templates under templates/windows/:

  • templates/windows/TesseraGameRunner.exe - Standalone Windows game runtime.
  • templates/windows/StandaloneBootstrapper.exe - Single-file launcher that extracts game payloads with the AGYPACK1 signature.
  • templates/windows/*.dll - Pre-bundled Windows runtime dependencies (GLFW, Jolt Physics, Lua, Vulkan Loader, libdeflate).

4.2 Exporting for Windows

  1. In the Tessera Editor on Linux, press Ctrl + B (File → Export Standalone Game...).
  2. Select Target Platform: Windows Standalone (.exe).
  3. Check Package as Single Executable if you want a single portable .exe.
  4. Click Export Game. The resulting exports/<GameTitle>_Windows/ package is ready to distribute to Windows gamers.

Updating Windows Templates

Windows templates only need to be rebuilt when you modify low-level engine C++ code (e.g., adding new C++ engine systems or modifying shaders). When building on Windows, run:

cmake --build build --config Release --target windows_export_template

This refreshes the binaries in templates/windows/ for all contributors.
