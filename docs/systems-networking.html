Multiplayer Architecture & Authority Model

Tessera implements a high-performance authoritative Client-Server multiplayer architecture inspired by Godot Engine's authority design (src/Networking/), featuring fine-grained per-node authority delegation, authoritative state replication packets, authority shields, and Remote Procedure Calls (RPCs).

1. The Godot-Style Authority Model

In Tessera, every node in the scene graph has a multiplayerAuthority property (a 32-bit unsigned integer representing a network Peer ID):

  • Peer ID 1: Always represents the Server / Host.
  • Peer ID 2+: Represents connected Clients (Peer 2, Peer 3, Peer 4, etc.).
ℹ Why Per-Node Authority?

Instead of either the server simulating everything or clients trusting each other arbitrarily, each entity has an explicit master. The server owns the global world (monsters, doors, day/night cycle, economy), while each client is assigned authority over their own player avatar.

2. State Replication & The Authority Shield

Multiplayer synchronization occurs at a fixed network tick rate (default 20 Hz / 30 Hz):

  1. Outbound Replication Filtering: Each peer only sends state updates for nodes it currently owns: 
    if (node->multiplayerAuthority != m_localPeerId) continue; // Don't send what we don't own!
  2. Inbound Authority Shield: When receiving state updates from a remote peer, the engine validates ownership before applying changes: 
    if (node->multiplayerAuthority == m_localPeerId) return; // Discard! Remote peer cannot override our node!

This completely prevents malicious or desynced clients from moving the server's NPCs, teleporting other players, or altering world geometry.

3. Remote Procedure Calls (RPC)

Peers communicate gameplay events across the network using RPCs:

Delivery ModeProtocolUse Cases
ReliableSequenced TCP / Reliable UDPSpawning characters, dealing damage, inventory transactions, chat messages, setting authority.
UnreliableFast UDP DatagramsCosmetic particle effects, camera shake triggers, footstep sound triggers.

Handing Off Authority via RPC

When a player logs into your game or joins a server:

-- Server spawns a character for the incoming client (e.g. Peer 2)

function on_player_connected(peer_id)

    local avatar = Scene.add_character_node("Player_" .. peer_id)

    avatar:set_multiplayer_authority(peer_id)

    

    -- Notify all connected clients of the new authority assignment

    Network.rpc("SetAuthority", avatar:get_id(), peer_id)

end

4. The Multiplayer & Networking Window

Accessible via Shift+P or Window → Multiplayer & Networking:

  • Host Server Button: Launches the authoritative simulation server on the configured port (default 7777). Sets local peer ID to 1.
  • Connect Client Button: Connects to a remote or local host IP address. Receives assigned client peer ID.
  • Peer List & Ping Monitor: Shows all connected clients with live round-trip latency (ping) and packet replication rates.
  • Interactive Authority Inspector: View and reassign any node's multiplayerAuthority with a single click.
  • RPC Test Console: Send test remote procedure calls with custom string and integer payloads to any peer.

4. Declarative Multiplayer Property Sync

In addition to authoritative transforms, Tessera supports declarative, per-property synchronization rules inspired by modern multiplayer networking patterns:

Replication ModeEnum ValueBandwidth Profile & Description
On ChangeReplicationMode::OnChangeOnly broadcasts an update when the property's numerical or string value actually changes, throttled to a configurable maximum frequency (e.g. 20 Hz). Minimizes packet sizes for health, animation states, colors, and inventory counters.
ContinuousReplicationMode::ContinuousTransmits property state on every network tick regardless of change. Best suited for high-frequency physics transforms and simulated velocities.

Configuring Declarative Replication in Lua

function OnInit(self)
    -- Enable declarative replication for this entity
    self:SetReplicationEnabled(true)

    -- Synchronize position and animation state whenever they mutate
    self:AddReplicationRule("position", "OnChange", 20.0)
    self:AddReplicationRule("animState", "OnChange", 20.0)
    self:AddReplicationRule("color", "OnChange", 10.0)
end
